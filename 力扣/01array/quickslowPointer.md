# 📝 刷题总结：LeetCode 26. 删除有序数组中的重复项

## 一、题目核心要求

原地删除重复元素，不能新建数组（空间复杂度必须 O (1)）。
返回去重后的数组长度。
原数组的前 **返回长度** 个元素必须是去重后的结果（顺序不能乱）。

## 二、最优解法：快慢指针法（单层循环）

### 1. 思想隐喻

把数组想象成一条传送带：

- 慢指针 `slow`：像个管家，守在已经去好重的区域末尾，负责腾出新位置。
- 快指针 `quick`：像个侦察兵，在前面跑，负责寻找和管家手里不一样的元素。

### 2. 标准代码模板

```
int removeDuplicates(int* nums, int numsSize) {
    if (numsSize == 0) return 0; // 边界防守：空数组直接返回0

    int slow = 0; // slow 从 0 开始，指向已确认的不重复区域的尾部
    for (int quick = 1; quick < numsSize; quick++) {
        if (nums[quick] != nums[slow]) { // 侦察兵找到了新元素
            slow++;                      // 管家往前走一步，腾出位置
            nums[slow] = nums[quick];    // 把新元素放进管家的新位置
        }
        // 如果相等，什么都不做，侦察兵继续往前跑
    }

    return slow + 1; // slow是下标，0~slow共 slow+1 个元素
}
```

## 三、踩坑记录与避雷指南（重点！）

🚨 **坑 1：C 语言传数组的 “退化” 陷阱**
现象：在函数内使用 `sizeof(arr) / sizeof(arr[0])` 试图计算长度，结果得到 1 或 2。
本质：`void func(int arr[])` 传参时，数组退化为指针，函数丢失了长度信息。
避雷：永远在函数外部计算好长度，把长度作为第二个参数传进去！

🚨 **坑 2：嵌套 while 循环的越界死循环**
现象：为了跳过连续重复项，写了内层 `while(arr[quick] == arr[slow]) quick++;`，导致 quick 越界访问内存，多输出乱码（如多出一个 0）。
本质：C 语言不检查数组越界，内层循环没有加上 `quick < len` 的边界保护。
避雷：双指针去重，强烈建议用单层 `for` 循环！让 quick 每次只走一步，用 if 判断是否重复，彻底杜绝越界风险，且代码更精炼。

🚨 **坑 3：返回值计算错误**
现象：搞不清该返回 `slow` 还是 `slow + 1`。
本质：slow 是数组下标（从 0 开始），长度是从 1 开始。
避雷：去重后有效区间的下标是 `0 ~ slow`，共 `slow - 0 + 1` 个元素，所以返回 `slow + 1`。

## 四、复杂度分析

表格

| 解法 | 时间复杂度 | 空间复杂度 | 实际执行效率 |
| --- | --- | --- | --- |
| 嵌套 while 循环 | O(n) | O(1) | 较慢（频繁跳转，判断次数多） |
| 单层 for 循环 | O(n) | O(1) | 极快（逻辑直线执行，CPU 缓存友好） |

> 
> 为什么单层循环更快？
> 虽然两者时间复杂度都是 O (n)，但单层循环没有嵌套的分支跳转，对 CPU 的分支预测更友好，常数项时间更小。
