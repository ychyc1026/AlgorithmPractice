# 刷题总结：LeetCode 209. 长度最小的子数组（完整复盘版）

------

## 一、两种可 AC 代码（带思考注释）

### 1. 标准框架版（推荐：面试 / 刷题首选）

核心思想：**枚举每一个右边界，针对每个右边界优化左边界**。一层循环只干一件事，逻辑闭环，通用性最强。

```
#include <climits>
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int back = 0;          // 左边界：窗口左端点
        int sum = 0;           // 窗口状态：当前窗口内元素和
        int minLen = INT_MAX;  // 结果：求最小值，初始设为极大值
        int n = nums.size();   // 数组总长度，用size()获取，避免反复调用

        // 外层循环：枚举每一个右边界 front
        for (int front = 0; front < n; front++) {
            // 第一步：将当前右边界元素纳入窗口，更新状态
            sum += nums[front];

            // 第二步：只要窗口满足条件，就收缩左边界，尝试更优解
            while (sum >= target) {
                // ✅ 先更新答案：此时窗口合法，当前长度有资格成为候选
                int curLen = front - back + 1;
                if (curLen < minLen) {
                    minLen = curLen;
                }
                // 移出左边界元素，右移左指针
                sum -= nums[back];
                back++;
            }
            // 退出内层循环：当前右边界已优化到极致，处理下一个右边界
        }

        // 边界处理：全程没找到合法窗口，按题目要求返回0
        return minLen == INT_MAX ? 0 : minLen;
    }
};
```

### 2. 我的思路版（if-else 交替 + do-while 收缩）

核心思想：**根据 sum 状态交替移动左右指针**，sum 小就扩右，sum 够就缩左；利用「收缩时窗口长度单调递减」的特性，只在收缩前后更新两次 min。

```
#include <climits>
class Solution {
public:
    int minSubArrayLen(int target, vector<int>& nums) {
        int front = 0;
        int back = 0;
        int sum = 0;
        int len = 0;        // 手动维护的窗口长度，不与指针实时绑定
        int min = INT_MAX;  // 修复：求最小值初始化为极大值，不能为0
        int n = nums.size();

        while (front < n) {
            if (sum < target) {
                // sum不足：右移front，扩大窗口
                sum += nums[front++];
            }
            else {
                // ✅ 第一次更新：刚进入合法状态，先记录当前窗口
                // 防止漏掉「front刚凑够sum」的初始最优解
                len = front - back + 1;
                if (len < min)
                    min = len;

                // do-while 一次性收缩左边界，直到sum不满足
                do {
                    // 修复：先减元素，再右移back，顺序不能反
                    sum -= nums[back];
                    back++;
                    len--;
                } while (sum >= target);

                // ✅ 第二次更新：回退一步，拿到收缩阶段最后一个合法窗口的长度
                // 利用单调性：收缩过程长度递减，最后一个合法窗口就是本轮最小
                len++;
                if (len < min)
                    min = len;
            }
        }

        // 修复：无解情况返回0，不能直接返回INT_MAX
        return min == INT_MAX ? 0 : min;
    }
};
```

## 二、本题思考与踩坑总结

### 1. 题目核心

给定正整数数组 `nums` 和目标值 `target`，找出和 ≥ target 的**长度最小的连续子数组**，不存在则返回 0。

- 关键前提：数组元素全为正整数 → 窗口和具有严格单调性 → 可以使用滑动窗口 O (n) 解法

### 2. 我的踩坑全记录

#### 坑 1：最小值初始化错误

- 错误：`int min = 0;`
- 原因：求最小值初始化为 0，后续所有合法长度都≥1，永远无法更新 min，最终返回 0
- 结论：求最小值初始用`INT_MAX`，求最大值初始用`INT_MIN`

#### 坑 2：do 循环内指针顺序颠倒

- 错误：先`back++`，再`sum -= nums[back]`
- 原因：跳过了当前左边界元素，减掉的是下一个位置的值，sum 计算完全错误
- 结论：永远遵循「先处理元素值，再移动指针」的顺序

#### 坑 3：漏掉初始合法窗口

- 错误：一进入 else 直接进入 do 收缩，不先记录当前窗口
- 原因：front 刚把 sum 凑够的第一个窗口，本身就可能是全局最优，直接收缩会丢失
- 结论：只要窗口变为合法，先更新答案，再做收缩

#### 坑 4：len 变量与指针不同步

- 问题：手动维护 len 变量，通过`len--`、`len++`调整，不与 front/back 实时计算
- 风险：一旦指针操作和 len 操作不同步，数值就会失真，属于 “手动快照” 式维护
- 结论：优先用`front - back + 1`实时计算，减少独立变量

#### 坑 5：无解情况未处理

- 错误：直接`return min;`
- 原因：数组总和小于 target 时，min 始终是 INT_MAX，题目要求返回 0
- 结论：最终必须判断极值是否被更新过，未更新则返回 0

#### 坑 6：vector 长度获取

- 知识点：vector 数组长度通过`nums.size()`获取，返回类型为`size_t`（无符号整数）
- 注意：不能在函数内用`sizeof(nums)/sizeof(nums[0])`计算，vector 传参会退化为指针，大小信息丢失

### 3. 两种写法的本质对比

表格

| 维度     | 标准框架版                           | 我的思路版                             |
| -------- | ------------------------------------ | -------------------------------------- |
| 思维模式 | 枚举右边界，每个右边界独立优化左边界 | 过程模拟，根据 sum 状态交替移动指针    |
| 答案更新 | 每个合法窗口都更新，不漏解           | 只更新两次（初始窗口、收缩后最小窗口） |
| 长度计算 | 实时`front-back+1`，永远同步         | 手动维护 len，容易脱节                 |
| 通用性   | 所有滑动窗口题通用                   | 仅适用于强单调性的简单题               |
| 出错概率 | 低，职责单一                         | 高，边界和变量维护易出错               |

## 三、滑动窗口算法思维升华

### 1. 滑动窗口的核心前提：单调性

滑动窗口能把暴力 O (n²) 降到 O (n)，本质是利用了**窗口状态的单调性**：

- 右边界右移 → 窗口扩大 → 状态量（和、字符种类数等）单调递增
- 左边界右移 → 窗口缩小 → 状态量单调递减

正因为单调，左指针不需要回溯，每个元素最多进窗口一次、出窗口一次，总复杂度 O (n)。 本题中「收缩时窗口长度单调递减」，就是单调性的延伸结论。

### 2. 通用思维框架（万能模板）

所有滑动窗口题，都可以套用「**外层枚举右边界，内层优化左边界**」的标准框架：

```
初始化：
  left = 0
  窗口状态变量（sum、哈希表等）
  结果 = 极值

遍历 right 从 0 到末尾：
    1. 将 nums[right] 纳入窗口，更新状态
    
    while (窗口满足收缩条件)：
        ✅ 更新答案（此时窗口合法）
        2. 将 nums[left] 移出窗口，更新状态
        3. left++
```

这个框架的优势：

- 一层循环只承担一个职责，逻辑清晰
- 答案更新放在内层 while 开头，永远不会漏解
- 迁移性极强，换题只改状态变量和收缩条件

### 3. 两种思维模式对比

#### 「过程模拟」思维（我的初始思路）

- 特点：跟着状态走，状态不对就动指针，像在手动模拟整个过程
- 优点：直观，符合第一直觉
- 缺点：思维频繁切换，边界容易错，只能解决特定题目

#### 「枚举优化」思维（标准算法）

- 特点：主动分解问题，把大问题拆成 n 个 “以每个位置为右边界” 的子问题，逐个求最优
- 优点：结构化强，边界清晰，通用性强，是算法设计的标准思路
- 进阶：做题先搭框架，再填细节，而不是从头开始模拟过程

### 4. 配套 C++ 基础复盘

1. **vector 长度**：通过`.size()`获取有效元素个数，`.capacity()`获取底层总容量
2. **空 vector 禁忌**：空 vector 不能用下标`[]`赋值，必须用`push_back()`自动扩容，否则越界触发空指针错误
3. **INT_MAX**：int 类型最大值，头文件`<climits>`，用于求最小值时的初始极值
4. **传参退化**：vector 传引用`vector<int>&`避免拷贝，同时保证修改作用于原数组
